## Tech Debt

**Evaluation processor failure policy:**
- Issue: Parse, evaluation, transcript write, and Pub/Sub publish failures are marked with TODOs and do not share a single retry/DLQ/quarantine policy. `AlreadyExistsError` is handled, audio-segment annotation errors are logged and ignored, but generic transcript writes and Pub/Sub publish failures escape the processor.
- Files: `backend/pipeline/evaluation/processor.py:82`, `backend/pipeline/evaluation/processor.py:105`, `backend/pipeline/evaluation/processor.py:116`, `backend/pipeline/evaluation/processor.py:160`, `backend/pipeline/evaluation/tests/test_processor.py:154`
- Impact: A malformed or partially processed Pub/Sub event can create inconsistent state across transcripts, annotations, and alert publishing. Some failures skip silently, while others rely on Cloud Functions retry behavior without domain-specific classification.
- Fix approach: Define one evaluation error policy: poison-message handling for parse/validation, retryable vs non-retryable evaluator failures, idempotent transcript writes, and publish failure replay. Add tests that assert behavior for parse exceptions, service exceptions, transcript client errors, and Pub/Sub `future.result()` errors.

**Evaluation migration optionality:**
- Issue: Evaluation annotations are optional during the audio-segments migration. `AUDIO_SEGMENTS_API_URL` absence disables `AudioSegmentsClient`, and the processor writes annotations only when the client exists.
- Files: `backend/pipeline/evaluation/main.py:101`, `backend/pipeline/evaluation/main.py:104`, `backend/pipeline/evaluation/processor.py:127`, `backend/pipeline/evaluation/tests/test_processor.py:316`
- Impact: Evaluation decisions can exist in transcripts without corresponding audio-segment annotations, so UI and downstream consumers can disagree during deployment or configuration drift.
- Fix approach: Make the audio-segments client required for environments that serve the UI path, or emit a health-check failure/metric when annotation writes are disabled. Keep only explicit local/test bypasses.

**Broad lint and type-check suppressions:**
- Issue: Ruff enables `ALL` but globally ignores TODO markers, complexity, blind exception catches, several security rules, and many style constraints. `ty` excludes `model/` and `backend/services/local-whisper-api/`; notebooks and `model/colabs/**/*.py` are ignored by Ruff.
- Files: `pyproject.toml:77`, `pyproject.toml:88`, `pyproject.toml:92`, `pyproject.toml:116`, `pyproject.toml:141`, `pyproject.toml:147`, `pyproject.toml:175`, `pyproject.toml:178`, `pyproject.toml:214`, `pyproject.toml:235`
- Impact: The codebase depends on review discipline for complexity, exception hygiene, SQL construction, hardcoded credential patterns, and notebook/script correctness.
- Fix approach: Move ignores from global to narrow per-file scopes, track remaining suppressions as owned work items, and type-check `model/` and `backend/services/local-whisper-api/` with explicit exclusions only for generated or notebook-derived files.

**Generated artifact and Docker smoke-test drift:**
- Issue: Protobuf and TSOA generated outputs are excluded from git, generated by tasks/CI, and used by Docker images. CI smoke tests build ingestion and transcription images only, while the CI comment says evaluation/notification are excluded for missing proto generation even though their Dockerfiles generate protos.
- Files: `.gitignore:59`, `.gitignore:71`, `.mise.toml:129`, `frontend/api/package.json:15`, `frontend/api/package.json:17`, `.github/workflows/ci.yml:243`, `.github/workflows/ci.yml:250`, `.github/workflows/ci.yml:261`, `.github/workflows/ci.yml:270`, `backend/pipeline/evaluation/Dockerfile:25`, `backend/pipeline/notification/Dockerfile:25`
- Impact: A Docker-only import or generation failure in normalization, segmentation, evaluation, or notification images can pass CI. Comments and enforcement disagree, which makes the smoke matrix hard to trust.
- Fix approach: Smoke-build every deployable Dockerfile or document the exact excluded images with an issue reference. Keep the CI rationale in sync with Dockerfiles and generated-code tasks.

**Source-type registry coupling:**
- Issue: Adding a source type touches Python enums, SQL seed files, runtime specs, collector routing, settings caps, frontend shared types, and tests. Ingestion startup checks only the VM collector/cap invariant.
- Files: `backend/pipeline/storage/feed_store.py:53`, `backend/pipeline/storage/feed_store.py:58`, `backend/pipeline/ingestion/source_runtime_specs.py:41`, `backend/pipeline/ingestion/router.py:35`, `backend/pipeline/ingestion/main.py:34`, `terraform/modules/alloydb/sql/ingestion/006_seed_source_types.sql:4`, `frontend/common/src/types/feeds.ts:1`
- Impact: Non-ingestion paths can drift even when the VM startup invariant passes. A missing frontend type or seed row can surface as runtime validation failures instead of compile-time failures.
- Fix approach: Add a cross-language source-type manifest or contract test that compares SQL seed slugs, Python `SourceType`, runtime specs, API models, and frontend `SourceType`.

**Model notebooks and committed data artifacts:**
- Issue: `model/colabs/` contains active notebooks with TODOs while notebook Python and `.ipynb` files are broadly exempted from Ruff. `model/data/` is a committed artifact directory containing label exports and inference manifests.
- Files: `model/colabs/fine_tune_whisper.ipynb`, `model/colabs/evaluate_transcriptions.ipynb`, `model/data/README.md:3`, `model/data/label_studio_exports/playground_export.json`, `model/data/inference_manifests/playground_all_models.jsonl`, `pyproject.toml:175`, `.gitignore:88`
- Impact: Research and labeling workflows can accumulate unreviewed logic, licensing assumptions, or proprietary data artifacts outside the stricter application checks.
- Fix approach: Keep notebooks for exploration, but move reusable logic into tested `model/src/` modules. Add artifact review rules for new `model/data/**` files and keep large/proprietary outputs ignored.

## Known Bugs

**Unverified API proxy fallback authentication:**
- Symptoms: When API Gateway userinfo headers are absent, the proxy decodes bearer JWTs with `jose.decodeJwt` instead of verifying signature, issuer, and audience. Userinfo headers are also trusted if present.
- Files: `frontend/api/src/authentication.ts:22`, `frontend/api/src/authentication.ts:30`, `frontend/api/src/authentication.ts:44`, `frontend/api/src/authentication.ts:56`, `frontend/api/src/authentication.test.ts:159`
- Trigger: Any deployment path that can reach `frontend/api` directly without a trusted gateway can provide a forged userinfo header or unsigned/invalid JWT payload.
- Workaround: Keep the proxy reachable only through the trusted API Gateway and Cloud Run/IAM boundary until local verification is added.

**Fire Notifications duplicate segment selection:**
- Symptoms: Duplicate files with the same timestamp/name are deduplicated by keeping the first seen item.
- Files: `backend/pipeline/ingestion/collectors/fire_notifications/client.py:170`, `backend/pipeline/ingestion/collectors/fire_notifications/client.py:181`
- Trigger: The Fire Notifications API returns duplicate segment entries with the same filename/timestamp.
- Workaround: None in code beyond first-entry selection; fix after the upstream/new API supports stable duplicate resolution.

**API docs selects the first API config:**
- Symptoms: Docs endpoint lists API Gateway APIs and selects the first API plus newest config instead of using an explicit API ID.
- Files: `frontend/api/src/docs/docsController.ts:30`, `frontend/api/src/docs/docsController.ts:33`, `frontend/api/src/docs/docsController.ts:42`, `frontend/api/src/docs/docsController.ts:54`
- Trigger: More than one API exists in the project, or API listing order does not match the intended docs target.
- Workaround: Keep one API in the project or add an environment variable for the API ID.

**Evaluation validation raises outside the TODO failure path:**
- Symptoms: Missing `segment_id`, `feed_id`, `transcript`, or `source_audio_uris` raises `ValueError` inside `process_event` rather than producing a classified bad-message result.
- Files: `backend/pipeline/evaluation/processor.py:91`, `backend/pipeline/evaluation/processor.py:94`, `backend/pipeline/evaluation/processor.py:100`
- Trigger: A transcribed-audio Pub/Sub message is parseable but incomplete.
- Workaround: Upstream producers must preserve required fields; add evaluation-side poison-message handling for durable protection.

**Segmentation inline documentation mismatch:**
- Symptoms: Deferred drain comments refer to a five-chunk bundle while `MAX_CHUNKS_PER_WINDMILL_BUNDLE` is `10`.
- Files: `backend/pipeline/segmentation/constants.py:27`, `backend/pipeline/segmentation/transforms/stateful.py:1031`
- Trigger: Maintainers tune bundle sizing or reason from comments instead of constants.
- Workaround: Treat `backend/pipeline/segmentation/constants.py` as authoritative and update comments with the constant.

## Security Considerations

**API proxy auth verification boundary:**
- Risk: Forged gateway userinfo headers or unsigned JWT payloads can determine `request.user`, including the email used for admin-group lookup.
- Files: `frontend/api/src/authentication.ts:22`, `frontend/api/src/authentication.ts:30`, `frontend/api/src/authentication.ts:56`, `frontend/api/src/feeds/feedsController.ts:259`, `frontend/api/src/rules/rulesController.ts:290`
- Current mitigation: Controllers use `@Security('google_id_token')` and API Gateway backend extensions; mutation endpoints check `request.user.isAdmin`.
- Recommendations: Verify ID tokens locally with Google public keys, issuer, audience, and expiry for the bearer-token path. Reject userinfo headers unless the request is proven to come from the gateway, or terminate direct access to the proxy at IAM/network level.

**Admin group absence grants admin:**
- Risk: If `WORKSPACE_ADMIN_GROUP_EMAIL` is unset, `checkIsAdmin` returns `true` for any authenticated email.
- Files: `frontend/api/src/config.ts:66`, `frontend/api/src/config.ts:132`, `frontend/api/src/config.ts:133`
- Current mitigation: Admin checks exist in feed/rule mutation controllers.
- Recommendations: Fail closed in non-local environments when the admin group is missing. Keep a local/test-only override separate from production configuration.

**Python service auth depends on `IS_GCP`:**
- Risk: FastAPI services bypass OIDC verification whenever `IS_GCP` is not exactly `true`. Token verification also calls `verify_oauth2_token` without an explicit audience.
- Files: `backend/pipeline/common/env.py:4`, `backend/pipeline/common/auth.py:30`, `backend/pipeline/common/auth.py:49`, `backend/services/feeds/main.py:46`, `backend/services/rules/main.py:33`, `backend/services/transcripts/main.py:33`, `backend/services/audio_segments/main.py:46`
- Current mitigation: Terraform/deployment is expected to set `IS_GCP=true`, and service-to-service clients fetch ID tokens in GCP.
- Recommendations: Use an explicit environment mode for local auth bypass, fail closed for unknown environments, and validate expected audience for each service.

**Committed local environment file pattern:**
- Risk: `local_dev/LOCAL.env` is present in the repository while `.gitignore` ignores `.env*` but not arbitrary `*.env` names. This increases the chance that local development values become committed.
- Files: `local_dev/LOCAL.env`, `.gitignore:16`, `.mise.toml:171`, `.github/workflows/integration-tests.yml:77`
- Current mitigation: Env example files exist and `.env*` files are ignored; this audit only notes file existence, not contents.
- Recommendations: Rename committed local defaults to a non-secret template name, ignore `*.env`, and generate local env files from examples or scripts.

**Credential and PII logging hygiene:**
- Risk: Admin membership checks log member email and group ID; Cloud Identity errors log normalized email plus provider error data. Secret Manager access failures log the secret resource name.
- Files: `frontend/api/src/config.ts:111`, `frontend/api/src/config.ts:170`, `backend/pipeline/ingestion/collectors/bcfy_calls/bcfy_calls_collector.py:117`, `backend/pipeline/ingestion/collectors/bcfy_calls/bcfy_calls_collector.py:120`
- Current mitigation: Tokens and password values are not intentionally logged in these paths.
- Recommendations: Redact or hash user email in routine logs, keep group IDs out of normal info logs, and avoid logging full secret resource names unless needed for incident response.

## Performance Bottlenecks

**Feed listing and tag filtering scale linearly:**
- Problem: The UI fetches every feed page for `listFeeds`, and feed search/configuration views issue an additional unfiltered all-feeds query to derive filter tags. Backend list queries also run a filtered count for every page.
- Files: `frontend/transcription-ui/src/service/listFeeds.ts:58`, `frontend/transcription-ui/src/service/listFeeds.ts:65`, `frontend/transcription-ui/src/components/feeds/FeedSearchView.tsx:270`, `frontend/transcription-ui/src/components/feeds/FeedConfigurationView.tsx:116`, `backend/pipeline/storage/feed_store.py:915`, `backend/pipeline/storage/feed_store.py:925`, `backend/pipeline/storage/feed_queries.py:568`
- Cause: Pagination is flattened client-side, backend tag dictionary support is missing, and `COUNT_FEEDS_SQL` runs alongside page fetches.
- Improvement path: Use TanStack infinite queries for visible pages, add a backend filter-tag endpoint, make total counts optional or cached, and add indexes for tag/name filters if those remain hot.

**Unindexed feed name/tag filters:**
- Problem: Feed list SQL uses `fp.tags @> ...` and `f.name ILIKE '%...%'`, while visible ingestion indexes focus on lease acquisition and HOT-safe feed updates.
- Files: `backend/pipeline/storage/feed_queries.py:451`, `backend/pipeline/storage/feed_queries.py:453`, `backend/pipeline/storage/feed_queries.py:454`, `backend/pipeline/storage/feed_queries.py:574`, `terraform/modules/alloydb/sql/ingestion/018_feeds_hot_indexes.sql:12`, `terraform/modules/alloydb/sql/ingestion/021_feed_properties_tags.sql:3`
- Cause: `feed_properties.tags` has validation but no visible GIN index, and substring name search lacks a visible trigram/search index.
- Improvement path: Add production query plans for feed search. Add a GIN index for tag containment and a trigram/full-text strategy for name search if query plans show table scans.

**Feed recovery path sort limit:**
- Problem: Recovery claim SQL can become expensive when failing/abandoned rows spike or the pg_cron sweep stalls.
- Files: `backend/pipeline/storage/feed_queries.py:288`, `backend/pipeline/storage/feed_queries.py:296`, `backend/pipeline/storage/feed_queries.py:300`, `terraform/modules/alloydb/sql/ci/hot_protection_check.sql`
- Cause: The recovery path relies on structurally small volumes; active-abandoned rows use `idx_feeds_active` plus a sort.
- Improvement path: Monitor recovery P99 and add the documented partial recovery index with HOT-protection allow-list updates when the threshold is reached.

**Stateful segmentation backlog processing:**
- Problem: Dataflow stateful DoFns must stay within Windmill's 300-second bundle lease. Large per-feed backlogs are split into self-chaining timer bundles capped by `MAX_CHUNKS_PER_WINDMILL_BUNDLE`.
- Files: `backend/pipeline/segmentation/transforms/stateful.py:30`, `backend/pipeline/segmentation/transforms/stateful.py:46`, `backend/pipeline/segmentation/transforms/stateful.py:60`, `backend/pipeline/segmentation/constants.py:27`
- Cause: Stateful work is sequential per key and downstream audio/VAD work has variable latency.
- Improvement path: Keep `MAX_CHUNKS_PER_WINDMILL_BUNDLE` tied to measured per-chunk latency, and test restart/backlog scenarios before raising VAD/transcription work per chunk.

**Ingestion worker concurrency ceiling:**
- Problem: Ingestion targets 250 concurrent feeds per worker and depends on heartbeat, DB pool, GCS connection pool, and per-source cap tuning.
- Files: `backend/pipeline/ingestion/collector_runtime.py:103`, `backend/pipeline/ingestion/collector_runtime.py:153`, `backend/pipeline/ingestion/collector_runtime.py:173`, `backend/pipeline/ingestion/source_runtime_specs.py:47`, `backend/pipeline/ingestion/source_runtime_specs.py:55`, `backend/pipeline/ingestion/source_runtime_specs.py:68`, `backend/pipeline/ingestion/source_runtime_specs.py:75`
- Cause: A single runtime manages event-loop tasks, a heartbeat thread, a memory watchdog, GCS uploads, Pub/Sub publishes, and lease writes.
- Improvement path: Treat cap changes as capacity changes. Load-test with representative audio and failure rates before raising caps or max feeds per worker.

## Scaling Limits

**Ingestion VM capacity:**
- Current capacity: Design target is 250 concurrent feeds per GCE instance, with default per-worker source caps of 240 `bcfy_feeds`, 600 `bcfy_calls`, 900 `openmhz`, and 300 `fire_notifications`.
- Limit: Raising caps without DB/GCS/Pub/Sub/event-loop validation can increase memory, heartbeat latency, and lease false-positive risk.
- Scaling path: Scale horizontally through the MIG and tune per-source caps in `backend/pipeline/ingestion/source_runtime_specs.py`/environment after load tests.

**Dataflow stateful bundle processing:**
- Current capacity: `MAX_CHUNKS_PER_WINDMILL_BUNDLE` is 10 chunks per stateful bundle.
- Limit: Dataflow Windmill has a 300-second wall-clock bundle lease; per-chunk latency increases reduce safe backlog-drain size.
- Scaling path: Reduce bundle chunk cap or move heavy work out of stateful DoFns if per-chunk processing approaches the bundle lease.

**Feed UI/search:**
- Current capacity: Client code explicitly identifies 10k+ feeds as a scaling concern for `listFeeds`.
- Limit: Full pagination loops plus all-feed tag extraction add many API calls and large in-browser arrays.
- Scaling path: Backend tag aggregation, server-side filtering, infinite query pagination, and optional totals.

**Recovery feed claiming:**
- Current capacity: Recovery path assumes small failing/abandoned volumes, with comments referencing roughly 500 failing-or-abandoned rows as the safe operating shape.
- Limit: pg_cron pauses or failure storms make recovery sorting expensive.
- Scaling path: Add `idx_feeds_recovery` from the documented TODO after query metrics justify the extra HOT-protection allowance.

## Dependencies at Risk

**TSOA alpha dependency:**
- Risk: API route/spec generation depends on `tsoa` `^7.0.0-alpha.0`.
- Impact: Alpha changes can break generated routes, decorators, or OpenAPI output.
- Migration plan: Pin an exact alpha in `frontend/api/yarn.lock` and plan an upgrade to a stable `tsoa` release with `yarn generate-routes` and `yarn verify-spec` checks.

**Lower-bound-only Python dependencies:**
- Risk: Many Python dependencies use `>=` ranges across root and package `pyproject.toml` files.
- Impact: `uv.lock` stabilizes normal installs, but package exports, Docker `uv export`, or lock refreshes can admit breaking upstream releases.
- Migration plan: Keep `uv.lock` reviewed, add upper bounds for high-risk runtime libraries, and run full backend plus Docker smoke tests on lock refreshes.

**Toolchain version drift:**
- Risk: `.tool-versions` pins `uv`, Python, Node, Terraform, and `jq`, while Dockerfiles copy a different `uv` binary version from `ghcr.io/astral-sh/uv`.
- Impact: Local/CI dependency resolution and Docker dependency export can differ.
- Migration plan: Align Docker `uv` image tags with `.tool-versions` or document the Docker-specific version policy.

**Model optional dependency surface:**
- Risk: `model/pyproject.toml` keeps multiple optional extras for audio, scoring, Vertex, and training while `model/` is excluded from `ty`.
- Impact: Optional extras can break without type-check coverage across the whole model package.
- Migration plan: Add focused CI jobs for each model extra or a matrix that installs `model[dev,scoring,vertex,audio]` and runs package tests.
