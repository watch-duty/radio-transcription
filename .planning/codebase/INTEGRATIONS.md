# External Integrations

**Analysis Date:** 2026-05-27

## APIs & External Services

**Google Cloud Platform:**
- Google Cloud Pub/Sub - ordered event bus for raw audio chunks, normalized audio, transcribed audio, evaluation results, notifications, and local emulation.
  - SDK/Client: `google-cloud-pubsub` via `backend/pipeline/common/clients/pubsub_client.py`, `backend/pipeline/common/gcp_helper.py`, `backend/pipeline/transcription/main.py`, and `local_dev/pubsub_init.py`.
  - Auth: ADC/service account in production; local emulator via `PUBSUB_EMULATOR_HOST` in `local_dev/run_evaluation_publish.py` and `local_dev/pubsub_init.py`.
- Google Cloud Storage - audio staging/canonical storage, schema migration file staging, ASR manifests/results, Echo source events, and browser audio playback URLs.
  - SDK/Client: `google-cloud-storage` and `gcloud-aio-storage` in `backend/pipeline/common/clients/gcs_client.py`, `backend/pipeline/common/storage/gcs_uploader.py`, `backend/pipeline/ingestion/collectors/echo/main.py`, and `model/colabs/common/gcs_utils.py`.
  - Auth: ADC/service account; local emulator via `STORAGE_EMULATOR_HOST` in integration tests and `local_dev/gcs_init.py`.
- Google Cloud Speech-to-Text V2 / Chirp V3 - synchronous transcription of normalized GCS audio.
  - SDK/Client: `google-cloud-speech` in `backend/pipeline/transcription/transcribers/chirp.py`.
  - Auth: ADC/service account with `PROJECT_ID`, `TRANSCRIBER_TYPE`, and `TRANSCRIBER_CONFIG` read by `backend/pipeline/transcription/main.py`.
- Google Cloud Logging and Cloud Trace - production logging and OpenTelemetry trace export.
  - SDK/Client: `google-cloud-logging`, `opentelemetry-exporter-gcp-trace`, and OpenTelemetry SDK in `backend/pipeline/common/logging.py` and `backend/pipeline/common/tracing_utils.py`.
  - Auth: ADC/service account; enabled only when `IS_GCP=true` per `backend/pipeline/common/env.py`.
- Google Cloud Monitoring - custom metric emission for feed queue/autoscaling.
  - SDK/Client: `google-cloud-monitoring` in `backend/pipeline/common/clients/monitoring_client.py` and `backend/pipeline/ingestion/oldest_feed_publisher/main.py`.
  - Auth: ADC/service account; project from `GOOGLE_CLOUD_PROJECT`.
- Google Secret Manager - Broadcastify JWT storage/rotation and AlloyDB schema migration password access.
  - SDK/Client: `google-cloud-secret-manager` in `backend/pipeline/ingestion/collectors/bcfy_calls/bcfy_calls_collector.py`, `backend/pipeline/ingestion/broadcastify_credential_rotation/main.py`, and `terraform/modules/alloydb/main.tf`.
  - Auth: ADC/service account; secret IDs from `BROADCASTIFY_JWT_SECRET_ID` and Terraform `password_secret_id`.
- Google API Gateway Admin API - frontend API docs endpoint fetches the deployed OpenAPI spec from API Gateway.
  - SDK/Client: `axios` plus `GoogleAuth` in `frontend/api/src/docs/docsController.ts`; API gateway shape is generated by `frontend/api/tsoa.json`.
  - Auth: Google OAuth access token with cloud-platform scope in `frontend/api/src/docs/docsController.ts`.
- Google Cloud Run / Cloud Functions Gen 2 - HTTP and CloudEvent execution platform for Python services and TypeScript proxy.
  - SDK/Client: Functions Framework in `backend/pipeline/*/Dockerfile`, `backend/pipeline/ingestion/*/Dockerfile`, `frontend/api/Dockerfile`, and Terraform module `terraform/modules/cloud_function/main.tf`.
  - Auth: Google OIDC identity tokens in `backend/pipeline/common/auth.py` and `google-auth-library` ID token clients in `frontend/api/src/*Controller.ts`.
- Google Dataflow - Apache Beam streaming runtime for normalization.
  - SDK/Client: `apache-beam[gcp]` in `backend/pipeline/normalization/pyproject.toml`, image `backend/pipeline/normalization/Dockerfile`, and options in `backend/pipeline/normalization/options.py`.
  - Auth: Dataflow worker service account/ADC.
- Firebase Hosting - static hosting for the React app.
  - SDK/Client: Firebase CLI expected by `CONTRIBUTING.md`; hosting config in `frontend/transcription-ui/firebase.json`.
  - Auth: Firebase/GCP project credentials outside repo.

**Radio Data Providers:**

  - Auth: `BROADCASTIFY_USERNAME` and `BROADCASTIFY_PASSWORD` in `backend/pipeline/ingestion/collectors/icecast/icecast_collector.py`.

## Data Storage

**Databases:**
- AlloyDB/PostgreSQL stores feeds, rules, transcripts, feed properties, audio segments, annotations, and leasing state.
  - Connection: `ALLOYDB_HOST`, `ALLOYDB_PORT`, `ALLOYDB_USER`, `ALLOYDB_PASSWORD`, `ALLOYDB_DB`, pool sizing, and timeout env vars in `backend/pipeline/storage/settings.py`.
  - Client: `asyncpg` pools in `backend/pipeline/storage/connection.py`, sync `psycopg` in `backend/pipeline/storage/sync_connection.py`, store classes in `backend/pipeline/storage/*_store.py`.
  - Schema: Terraform SQL migrations in `terraform/modules/alloydb/sql/ingestion/*.sql`; AlloyDB infrastructure in `terraform/modules/alloydb/main.tf`.
- Local PostgreSQL service supports local integration/E2E flows.
  - Connection: Docker Compose service in `docker-compose.yml`, override in `docker-compose.override.yml`, and local tests in `integration_tests/conftest.py`.
  - Client: `asyncpg` and `testcontainers` in `integration_tests` and `backend/pipeline/storage/tests`.

**File Storage:**
- Google Cloud Storage is the primary object store for staging audio, canonical/playback audio, Echo recordings, model manifests, SFT JSONL, inference outputs, schema migration SQL, and browser audio access.
  - Buckets: names provided by `AUDIO_STAGING_BUCKET`, `AUDIO_CANONICAL_BUCKET`, `ECHO_RECORDINGS_BUCKET`, model constants in `model/scripts/sft/pipeline.py`, and Terraform modules in `terraform/modules/gcs_bucket/main.tf`.
  - Clients: `backend/pipeline/common/gcp_helper.py`, `backend/pipeline/common/clients/gcs_client.py`, `backend/pipeline/common/storage/gcs_uploader.py`, `backend/pipeline/ingestion/collectors/echo/main.py`, and `model/colabs/common/gcs_utils.py`.
- Fake GCS server is used for local development and tests.
  - Configuration: `docker-compose.yml`, `local_dev/gcs_init.py`, and integration tests under `backend/pipeline/ingestion/collectors/tests`.
- AWS S3 is used by model data-source discovery for Echo and referenced by Fire Notifications/OpenMHz audio downloads.
  - Client: `boto3` in `model/data_sources/echo/s3_file_scanner.py`; HTTP S3-style downloads in `backend/pipeline/ingestion/collectors/fire_notifications/collector.py` and `backend/pipeline/ingestion/collectors/openmhz/collector.py`.

**Caching:**
- Redis/Memorystore deduplicates outgoing notifications.
  - Connection: `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, and `REDIS_CERTIFICATE_PATH` in `backend/pipeline/common/storage/redis_service.py`.
  - Client: `redis.Redis` with retry/backoff in `backend/pipeline/common/storage/redis_service.py`; Terraform module in `terraform/modules/memorystore_for_redis/main.tf`; local service in `docker-compose.yml`.
- In-process TTL cache stores fetched rule lists for remote evaluation.
  - Client: `cachetools.TTLCache` in `backend/pipeline/evaluation/rules_evaluation/evaluator.py`.

## Authentication & Identity

**Auth Provider:**
- Google OAuth 2.0 is the browser/user identity provider.
  - Implementation: React uses `@react-oauth/google` auth-code flow in `frontend/transcription-ui/src/main.tsx` and `frontend/transcription-ui/src/components/Login.tsx`; Express exchanges codes with `OAuth2Client` in `frontend/api/src/auth/authController.ts`.
  - Configuration: `VITE_GOOGLE_AUTH_CLIENT_ID` in `frontend/transcription-ui/src/main.tsx`, `GOOGLE_AUTH_CLIENT_ID`, and `GOOGLE_AUTH_CLIENT_SECRET` in `frontend/api/src/config.ts`.
- API Gateway and backend services use Google ID/OIDC tokens.
  - Implementation: TSOA `google_id_token` security definition in `frontend/api/tsoa.json`, JWT decode in `frontend/api/src/authentication.ts`, Cloud Run ID token calls in `frontend/api/src/*Controller.ts`, and FastAPI `verify_oidc_token` in `backend/pipeline/common/auth.py`.
  - Configuration: backend service URLs from `TRANSCRIPTS_API_URL`, `RULES_API_URL`, and `FEEDS_STORE_API_URL` in `frontend/api/src/config.ts`.
- Service-to-service calls fetch Google ID tokens from metadata/ADC.
  - Implementation: `backend/pipeline/common/auth.py`, `backend/pipeline/common/clients/transcripts_client.py`, `backend/pipeline/evaluation/rules_evaluation/evaluator.py`, and `backend/pipeline/notification/send_notification.py`.
- Broadcastify authentication uses API-key signed JWTs, Basic Auth, Secret Manager, and a scheduled rotation function.
  - Implementation: `backend/pipeline/ingestion/broadcastify_credential_rotation/main.py`, `backend/pipeline/ingestion/collectors/bcfy_calls/bcfy_calls_collector.py`, `backend/pipeline/ingestion/collectors/icecast/icecast_collector.py`, and `model/data_sources/broadcastify/bcfy_api.py`.

## CI/CD & Deployment

**Hosting:**
- React UI is built with Vite and hosted via Firebase Hosting config in `frontend/transcription-ui/firebase.json`.
- Frontend API is a Node Functions Framework HTTP service packaged by `frontend/api/Dockerfile` and described by `frontend/api/tsoa.json`.
- Backend HTTP APIs run as FastAPI/Uvicorn containers from `backend/services/transcripts/Dockerfile`, `backend/services/feeds/Dockerfile`, and `backend/services/rules/Dockerfile`.
- Pipeline functions run as Python Functions Framework containers from `backend/pipeline/transcription/Dockerfile`, `backend/pipeline/evaluation/Dockerfile`, `backend/pipeline/notification/Dockerfile`, and `backend/pipeline/ingestion/*/Dockerfile`.
- Normalization runs as a Dataflow Flex Template image from `backend/pipeline/normalization/Dockerfile`.
- Ingestion fleet runs in a GCE managed instance group provisioned by `terraform/modules/container_mig/main.tf`.

**CI Pipeline:**
- GitHub Actions CI runs Python lint/type/test, frontend lint/build/test, Terraform checks, Docker smoke tests, and SQL guard checks in `.github/workflows/ci.yml`.
- GitHub Actions integration workflow runs component and Docker Compose E2E tests in `.github/workflows/integration-tests.yml`.
- Deployment is triggered into a private repo by `.github/workflows/trigger-deploy.yml` when `terraform/modules/` or `protos/` changes.
- Linear PR-title automation runs through `.github/workflows/prepend-linear-issue-to-pr-title.yml`.

## Webhooks & Callbacks

**Incoming:**
- Browser/UI HTTP requests enter the frontend API routes generated by TSOA from `frontend/api/src/**/*Controller.ts` and configured by `frontend/api/tsoa.json`.
- Backend management APIs expose FastAPI routes in `backend/services/transcripts/main.py`, `backend/services/feeds/main.py`, and `backend/services/rules/main.py`.
- Pub/Sub push CloudEvents invoke transcription, evaluation, and notification functions in `backend/pipeline/transcription/main.py`, `backend/pipeline/evaluation/main.py`, and `backend/pipeline/notification/send_notification.py`.
- GCS object finalize events invoke Echo ingestion through `backend/pipeline/ingestion/collectors/echo/main.py`.
- Cloud Scheduler HTTP invocations target feed metrics publishing and Broadcastify credential rotation in `backend/pipeline/ingestion/oldest_feed_publisher/main.py` and `backend/pipeline/ingestion/broadcastify_credential_rotation/main.py`.
- Local Pub/Sub emulator push subscriptions are created by `local_dev/pubsub_init.py`.

**Outgoing:**
- Ingestion publishes raw audio `AudioChunk` messages to Pub/Sub in `backend/pipeline/common/gcp_helper.py` and `backend/pipeline/ingestion/normalizer_runtime.py`.
- Normalization reads Pub/Sub and writes normalized messages through Beam transforms in `backend/pipeline/normalization/orchestration.py` and `backend/pipeline/normalization/transforms/*`.
- Transcription publishes `TranscribedAudio` messages to Pub/Sub in `backend/pipeline/transcription/processor.py`.
- Evaluation writes transcripts through `backend/pipeline/common/clients/transcripts_client.py` and publishes rule-evaluation results through `backend/pipeline/evaluation/processor.py`.
- Notification fetches feed tags from the feeds API and posts alerts to an external notification endpoint in `backend/pipeline/notification/send_notification.py` and `backend/pipeline/notification/request_handler.py`.
- Frontend API calls backend Cloud Run services using Google ID tokens in `frontend/api/src/transcripts/transcriptsController.ts`, `frontend/api/src/feeds/feedsController.ts`, and `frontend/api/src/rules/rulesController.ts`.
- Browser audio playback converts `gs://` URIs to `https://storage.googleapis.com/` or local `/gcs/` proxy URLs in `frontend/transcription-ui/src/utils/audioUtils.ts`.
- Data-source collectors poll or stream from Broadcastify, OpenMHz, Fire Notifications, Echo/GCS, and S3-compatible URLs through `backend/pipeline/ingestion/collectors/*` and `model/data_sources/*`.
