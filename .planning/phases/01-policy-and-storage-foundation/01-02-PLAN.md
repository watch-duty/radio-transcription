<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source collectors -> shared collector helper | Source-specific signals become typed feed failures. |
| collector helper -> runtime | Typed FeedFailure instances cross into runtime failure handling. |
| tests -> collector call sites | AST validation checks current source files without executing source clients. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-01-13 | Tampering | HIGH | collector evidence construction | mitigate | Every current `collector_failure(...)` call must supply `policy_evidence=failure_policy.FailurePolicyEvidence(...)`; AST detector fails omissions. |
| T-01-14 | Denial of Service | HIGH | feed quarantine budget | mitigate | Evidence stays facts-only so budget/quarantine decisions remain centralized in `failure_policy.classify_failure_policy(...)`, not per-source verdict literals. |
| T-01-15 | Information Disclosure | MEDIUM | raw collector reasons | mitigate | Do not parse raw `reason` or `quarantine_reason` for policy routing; use enum facts and bounded existing reason behavior. |
| T-01-16 | Elevation of Privilege | LOW | Phase 1 collector surface | accept | No auth, API route, cryptography, or external authorization boundary is added in this plan. |
</threat_model>
