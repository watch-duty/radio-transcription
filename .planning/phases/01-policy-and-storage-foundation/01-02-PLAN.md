    status_reason = $5,
    status_reason_updated_at = NOW()
WHERE id = $1 AND worker_id = $2
  AND fencing_token = $3
  AND status = 'active'::feed_status
RETURNING status::text, failure_count, retry_after

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime -> storage | Runtime supplies feed id, worker id, fencing token, retry_after, and status_reason to a DB mutation. |
| storage -> database | SQL mutates feed lifecycle state in AlloyDB. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | HIGH | `RELEASE_NON_BUDGETED_FAILURE_SQL` | mitigate | Use fenced `WHERE id = $1 AND worker_id = $2 AND fencing_token = $3 AND status = 'active'::feed_status` so a caller without the active lease cannot mutate feed state. |
| T-01-06 | Denial of Service | HIGH | feed quarantine budget | mitigate | SQL must set `failure_count = 0` and tests must prove the non-budgeted path has no increment expression and no `quarantine_reason` assignment. |
| T-01-07 | Repudiation | MEDIUM | storage diagnostics | mitigate | Return `status::text, failure_count, retry_after` from SQL and return the status string from the store method so callers can log the actual state transition. |
| T-01-08 | Information Disclosure | LOW | storage method | mitigate | The non-budgeted method accepts canonical `FeedStatusReason` only and does not persist raw reason text or secrets. |
</threat_model>
