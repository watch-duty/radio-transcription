<threat_model>
Trust boundaries:
- GCS `config.json` is durable state from a previous phase and can be stale or
  manually edited.
- `gemini-sft eval` is a paid boundary once it calls Vertex batch inference.
- GCS `endpoint` is still valid tuning metadata but must not silently select an
  eval target in the new config contract.

STRIDE register:
- CFG-T4 repudiation/cost ambiguity: Eval can spend money using a target not
  declared in current config. Mitigation: `evaluate_run` validates
  `config.json["eval_models"]` before downloading manifests or submitting
  batch work.
- CFG-T5 stale fallback: An old config with `base_model` and `endpoint` can
  appear valid even though the operator did not choose targets. Mitigation:
  missing `eval_models` raises an actionable no-legacy-fallback error.
- CFG-T6 routing confusion: Phase 2 could accidentally implement partial
  backend selection. Mitigation: this plan only validates and records targets;
  Phase 3 owns executing configured targets by backend.
</threat_model>
