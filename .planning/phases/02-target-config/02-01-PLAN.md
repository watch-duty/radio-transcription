<threat_model>
Trust boundaries:
- External TOML configs are operator input and can contain unsafe paths,
  duplicate labels, stale fields, or model strings that should not be
  interpreted yet.
- Target labels flow into GCS artifact paths and report labels.
- Vertex resource strings are expensive to validate live, so Phase 2 must not
  call cloud APIs while parsing config.

STRIDE register:
- CFG-T1 path traversal/tampering: A target label can escape the normalized
  inference-manifest prefix if it is not constrained as a single safe segment.
  Mitigation: expose and reuse the artifact-label validator already used by
  `build_inference_manifest_blob_path`.
- CFG-T2 spoofing/collision: Two targets can share a label and overwrite or
  merge report/artifact rows. Mitigation: duplicate labels raise
  `RunConfigError` during config parsing.
- CFG-T3 elevation of stale config semantics: Legacy `base_model` or GCS
  `endpoint` fields can silently become eval targets. Mitigation: target
  parsing accepts only explicit `[[eval.models]]`; `CFG-04` is documented as
  superseded by D-05/D-09.
</threat_model>
