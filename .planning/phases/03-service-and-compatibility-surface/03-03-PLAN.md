<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/user -> BFF | BFF authenticates Google user and checks admin authorization. |
| BFF -> feeds-service | BFF authenticates as a service account and forwards internal actor context. |
| feeds-service route -> FeedService | Route validates caller trust and actor header before passing `actor_id`. |
| FeedService -> FeedStore | Service passes causal actor only; storage owns audit row construction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Spoofing | BFF actor derivation | mitigate | Derive actor only from authenticated `request.user.sub` after `isAdmin`; reject missing/invalid sub before downstream call. |
| T-03-03-02 | Spoofing | Feeds-service actor header | mitigate | Accept `X-WD-Actor-Id` only when authenticated caller email is trusted in GCP or local-dev mode is active. |
| T-03-03-03 | Tampering | Feed request body | mitigate | Keep actor IDs out of create/update/reset/deactivate/delete request bodies and assert this in API tests. |
| T-03-03-04 | Repudiation | FeedService fallback actor | mitigate | Remove admin-route `service:feeds-service` fallback and require explicit `actor_id`, preserving human attribution. |
| T-03-03-05 | Information Disclosure | Logs/errors | mitigate | Do not log raw tokens or full auth headers. Actor ID and caller email may appear only in structured operational context if needed. |
| T-03-03-06 | Elevation of Privilege | Trusted caller configuration | mitigate | Empty or missing production trust allowlist fails closed; only explicitly allowlisted BFF service accounts can forward actors. |
</threat_model>
