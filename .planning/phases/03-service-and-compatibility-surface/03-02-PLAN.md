<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| feeds-service -> BFF | Backend JSON names canonical diagnostic detail as `status_reason_detail`. |
| BFF -> browser | Public TypeScript/OpenAPI contract exposes camelCase `statusReasonDetail`. |
| UI data -> status tooltip | Existing UI renders diagnostic detail as optional display-only text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Information Disclosure | BFF/OpenAPI `Feed` schema | mitigate | Remove deprecated public `quarantineReason` alias so new consumers use the canonical bounded detail field. |
| T-03-02-02 | Tampering | BFF feed conversion | mitigate | Tests assert backend `status_reason_detail` is mapped directly to frontend `statusReasonDetail`; no request-body or client-supplied diagnostic detail is accepted. |
| T-03-02-03 | Denial of Service | UI status tooltip | accept | The detail text is already bounded at storage and rendered in existing tooltip paths; no new high-cost UI behavior is added. |
| T-03-02-04 | Repudiation | Diagnostic migration | mitigate | OpenAPI and tests prevent old/new contract drift that could hide current abnormal-state explanation from admins. |
</threat_model>
