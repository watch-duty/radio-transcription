<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Testcontainers database -> retention SQL | Real PostgreSQL-compatible execution validates the extension-free procedure semantics. |
| Retention procedure -> sequence table | Cleanup may remove ordering metadata only after both current feed and retained events are gone. |
| Executor -> local host | Testcontainers can consume Docker, CPU, memory, and process resources. |
| CI/prepared-machine verification -> release confidence | Resource-heavy verification may happen outside the local execution turn. |
| Prepared AlloyDB/CI -> pg_cron scheduler metadata | The scheduler lane must prove the production-only `*pg_cron*` migration applies and registers the expected DB-owned job. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | Retention procedure behavior | mitigate | Add DB-backed tests that call `CALL public.prune_feed_audit_events_retention()` and assert only expired rows are deleted. |
| T-05-03-02 | Repudiation | Retained feed_sequence ordering | mitigate | Add a test where retained rows keep sequence `[2]`, proving retention does not renumber history. |
| T-05-03-03 | Tampering | `feed_audit_event_sequences` pruning | mitigate | Add live-feed, deleted-feed-with-retained-history, and orphan-after-expiry tests for D-09 through D-11. |
| T-05-03-04 | Denial of Service | Local Testcontainers lane | mitigate | Keep local automatic verification to `py_compile`; require explicit human/prepared-machine verification before running Docker/Testcontainers. |
| T-05-03-05 | Repudiation | Rollback/concurrency evidence | mitigate | Include existing rollback, concurrent ordering, and delete-survival integration tests in the prepared-machine command. |
| T-05-03-06 | Tampering | AlloyDB pg_cron scheduler | mitigate | Add a blocking prepared AlloyDB/CI checkpoint that applies the `*pg_cron*` migration and queries `pg_extension`, `cron.job`, and the installed procedure body for the expected job name, schedule, command, and bounded retention SQL. |
