<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloud Run logs -> log-based metrics | Structured relay logs become Cloud Monitoring metric points. |
| Pub/Sub platform metrics -> alert policy | Managed Pub/Sub subscription metrics trigger operator notifications. |
| Terraform source -> production alert routing | Alert policy source controls production Slack notification routing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | I | log-based metrics | mitigate | Metrics filter on low-cardinality `relay_event` and `retryable`; no label extractors for event IDs, feed IDs, response bodies, secrets, or payload snapshots. |
| T-04-03-02 | D | alert policy noise | mitigate | Retryable failures require more than five events over five minutes; permanent/config and DLQ signals alert on any occurrence because they represent operator-actionable route failure. |
| T-04-03-03 | R | operations auditability | mitigate | Terraform-owned metric and alert names make live incidents traceable to source, and documentation points to the feed-audit triage flow. |
| T-04-03-04 | E | notification routing | mitigate | Reuse the existing nullable Slack channel pattern; dev has visible policies without secret channel data, prod routes only through the env-level channel resource. |
</threat_model>
