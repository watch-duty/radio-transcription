<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terraform source -> GCP control plane | Environment root changes create/update Cloud Logging, Pub/Sub, IAM, and Cloud Run routing resources. |
| Terraform outputs -> operator terminals/CI logs | Outputs are readable by operators and CI logs, so they must not contain secret values. |
| Pub/Sub -> Cloud Run | Route enablement activates authenticated push delivery to the relay service. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | S | Pub/Sub push subscription | mitigate | Preserve existing route module IAM/OIDC: push invoker service account, `roles/run.invoker`, OIDC audience set to relay service URL, and Pub/Sub token creator grant. |
| T-04-02-02 | I | Environment outputs | mitigate | Output only sink/subscription/endpoint/service identifiers; acceptance criteria grep for API keys, secret data, HMAC secrets, OAuth secrets, and Slack tokens. |
| T-04-02-03 | T | Production rollout flag | mitigate | Production route flag is explicit and release-gated, avoiding accidental reliance on a module default; no production route activation occurs without changing the tracked flag. |
| T-04-02-04 | E | Terraform deployer IAM | mitigate | This plan does not broaden deployer roles; it uses the existing route module's topic-scoped publisher and service-account-user grants. |
</threat_model>
