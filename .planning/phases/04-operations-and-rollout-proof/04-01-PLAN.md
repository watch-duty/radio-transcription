<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pub/Sub push -> Cloud Run relay | Externally delivered HTTP envelope crosses into the relay; Cloud Run IAM/OIDC is enforced by deployment but message content remains untrusted. |
| Relay -> Cloud Logging | Operational log fields leave process memory and become queryable by log viewers. |
| Relay -> Watch Duty | Existing WD client sends authenticated outbound webhook requests with `X-Api-Key`; this plan does not change that path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | S | `/pubsub/feed-audit-notifications` | transfer | Pub/Sub push authentication remains Cloud Run IAM/OIDC in deployment Terraform; this plan preserves endpoint behavior and does not create unauthenticated ingress. |
| T-04-01-02 | I | `main.py` logging | mitigate | Structured logs contain only `relay_event` and low-cardinality `failure_class`; tests assert no WD API key, `before_values`, or `after_values` leak. |
| T-04-01-03 | D | malformed message path | mitigate | Invalid envelopes still return HTTP 400 for Pub/Sub retry/DLQ and emit one structured warning; no additional parsing loop, network call, or database work is added. |
| T-04-01-04 | R | operational diagnosis | mitigate | Stable `relay_event` values make malformed/config failures attributable in Cloud Logging without relying on mutable textPayload strings. |
</threat_model>
