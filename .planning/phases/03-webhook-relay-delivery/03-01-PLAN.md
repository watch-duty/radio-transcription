<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Environment -> relay process | Env vars control WD destination and credential. |
| Pub/Sub -> relay HTTP endpoint | External HTTP request reaches the relay through Cloud Run IAM/OIDC. |
| Relay -> storage packages | Must remain separated; relay is not allowed to access AlloyDB. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-S01 | Spoofing | Relay endpoint | mitigate in Plan 04 | Deployment route must use authenticated Pub/Sub OIDC and Cloud Run invoker IAM; public code exposes only the expected path. |
| T-03-01-I01 | Information Disclosure | Settings/logging | mitigate | Do not log `WD_BACKEND_API_KEY`; tests should assert errors do not include secret values. |
| T-03-01-D01 | Denial of Service | Misconfigured relay | mitigate | Fail startup when WD base URL or API key is missing so bad revisions do not churn every Pub/Sub message. |
| T-03-01-T01 | Tampering | Relay/database boundary | mitigate | Add source-inspection tests blocking storage and DB imports; relay remains stateless and never touches AlloyDB. |
</threat_model>
