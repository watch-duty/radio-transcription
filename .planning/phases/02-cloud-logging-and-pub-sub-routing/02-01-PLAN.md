<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloud Logging -> Pub/Sub topic | Later Log Router sink writes routed LogEntries into the notification topic created here. |
| Pub/Sub push subscription -> DLQ topic | Later subscription dead-letters failed delivery attempts into the DLQ topic created here. |
| Deployment module -> app module | Topic/DLQ outputs become route module inputs and must not force environment roots to duplicate resources. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-E01 | Elevation of Privilege | Log Router sink writer IAM | mitigate in Plan 02 | This plan creates only the destination topic and name output; Plan 02 must grant `roles/pubsub.publisher` only on `topic_feed_audit_notification_name`, never project-wide. |
| T-02-01-S01 | Spoofing | Pub/Sub push to relay | mitigate in Plan 02 | This plan creates only topics; Plan 02 must require a dedicated push invoker service account plus Cloud Run `roles/run.invoker`. |
| T-02-01-S02 | Spoofing / Denial of Service | OIDC audience for path-based endpoint | mitigate in Plan 02 | This plan exposes topic inputs only; Plan 02 must set `oidc_token.audience = var.relay_service_url` while `push_endpoint` appends `/pubsub/feed-audit-notifications`. |
| T-02-01-D01 | Denial of Service / Availability | DLQ message retention | mitigate | Create `google_pubsub_subscription.feed_audit_notification_dlq_subscription` with `message_retention_duration = "604800s"` so messages dead-lettered after 10 attempts are retained for operator inspection. |
</threat_model>
