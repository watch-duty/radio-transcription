<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app module -> route module | App composition passes topic/DLQ outputs and relay inputs into route resources. |
| environment roots -> app module | Dev/prod roots remain thin and should not duplicate route resources. |
| relay input contract -> Cloud Run IAM/OIDC | Route enablement depends on real relay URL/name values, not fake relay resources. |
| static verification -> deployment safety | Grep/fmt/validate gates prevent unsafe IAM, audience, retry, and DLQ regressions before deploy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-E01 | Elevation of Privilege | App-wired sink publisher IAM | mitigate | Static validation must find `topic = var.notification_topic_name` and `member = google_logging_project_sink.feed_audit_notification.writer_identity`; no project-wide sink publisher grant is allowed. |
| T-02-03-S01 | Spoofing | App-wired Pub/Sub push | mitigate | The app module enables only the route module that uses dedicated `google_service_account.push_invoker` and Cloud Run `roles/run.invoker`; no unauthenticated push path is introduced. |
| T-02-03-S02 | Spoofing / Denial of Service | Relay path OIDC audience | mitigate | Static validation must find `audience = var.relay_service_url` and `/pubsub/feed-audit-notifications` together, proving the path endpoint does not rely on Terraform's default audience. |
| T-02-03-D01 | Denial of Service / Availability | Retry and DLQ behavior | mitigate | Static validation must find `minimum_backoff = "10s"`, `maximum_backoff = "60s"`, `max_delivery_attempts = 10`, and the DLQ retention subscription from Plan 01. |
| T-02-03-T01 | Tampering | Route ownership boundary | mitigate | The plan modifies only deployment app-module composition and validates that no feed-audit relay runtime, WD webhook implementation, producer code, or public Terraform resource is added. |
</threat_model>
