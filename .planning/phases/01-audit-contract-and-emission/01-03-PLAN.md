<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL row -> store method | Store methods receive database-returned rows that may contain nullable notification payloads. |
| store method args -> notification helper | Request-local method args must not become notification payload fields. |
| notification helper -> caller | Helper side effects must not change caller-visible feed write results. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-S01 | Spoofing | `FeedStore`, `SyncFeedStore` | mitigate | Pass only `row.get("feed_audit_event")` from SQL-returned rows to the helper; never build payloads from method parameters such as `feed_id`, `actor_id`, `reason`, or `status_reason`. |
| T-01-03-I01 | Information Disclosure | store integration | mitigate | Store methods do not add fields to the payload; sensitive-data control remains the existing audit allowlist from Plan 01/PAYLOAD-03. |
| T-01-03-D01 | Denial of Service | store write paths | mitigate | Use the shared helper from Plan 02, which catches local exceptions and never re-raises; do not add network clients, Pub/Sub, webhook calls, or extra DB reads. |
| T-01-03-R01 | Repudiation | async/sync helper usage | mitigate | Tests patch one shared helper in both stores to prove async and sync audited paths use the same emission boundary per AUDIT-04. |
</threat_model>
