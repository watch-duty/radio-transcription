<objective>
Extend the storage SQL contract so every audited async and sync feed write can
return the exact schema version 1 Feed Audit Notification payload as a single
nullable `feed_audit_event` column.

Purpose: the notification producer must be tied to the inserted audit row, not
to request-local guesses, and must not add a second database round trip.
Output: shared SQL payload builder, audited query result-column wiring, and
SQL contract tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| storage SQL -> Python store | Database-returned audit payload crosses into Python as trusted inserted-row data. |
| request/service args -> audit SQL | Untrusted or request-local feed mutation inputs must not directly shape notification payload fields. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-S01 | Spoofing | `feed_queries.py`, `sync_feed_queries.py` | mitigate | Build `feed_audit_event` only from `write_audit RETURNING` values via `feed_audit_event_payload_sql` per D-08; do not use request-local method fields for payload fields. |
| T-01-01-I01 | Information Disclosure | `feed_audit_sql.py` | mitigate | Reuse `before_values` and `after_values` from the existing audit snapshot allowlist; do not add raw request bodies, secrets, webhook-only fields, or broad feed columns per PAYLOAD-03. |
| T-01-01-D01 | Denial of Service | audited SQL statements | mitigate | Return payload data in the same audited statement and avoid extra database round trips per AUDIT-05/D-06. |
| T-01-01-T01 | Tampering | `feed_audit_event` result column | mitigate | Preserve one nullable JSONB result column named exactly `feed_audit_event` per D-07 and cover all audited SQL constants with contract tests. |
</threat_model>
