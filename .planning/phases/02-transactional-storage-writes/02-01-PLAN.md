<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service/API -> FeedStore | Callers pass only causal inputs such as `actor_id`; storage owns event construction. |
| FeedStore -> AlloyDB | SQL constraints enforce actor vocabulary, JSON object shape, sequence uniqueness, and diagnostic detail bounds. |
| Feed row -> audit snapshot JSON | Storage converts current-state rows into allowlisted audit snapshots. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Tampering | `feed_queries.ALLOCATE_FEED_AUDIT_SEQUENCE_SQL` | mitigate | Use `feed_audit_event_sequences` with `ON CONFLICT (feed_id) DO UPDATE ... RETURNING`; tests reject `MAX(feed_sequence)` per D-18 through D-20. |
| T-02-01-02 | Spoofing | Actor vocabulary in docs and SQL | mitigate | Remove `system:` and keep database suffix checks for `service:`, `job:`, `gcp-sa:`, `user:google:`, `user-email:`, and exact `unknown:unknown` per D-16. |
| T-02-01-03 | Information Disclosure | Snapshot query allowlist | mitigate | Query tests require allowlisted fields and reject raw `SELECT f.*`, `SELECT fp.*`, lease fields, heartbeat fields, and fencing fields per D-12 and D-13. |
| T-02-01-04 | Tampering | Audit/current-state transaction boundary | mitigate | This plan creates only SQL primitives; downstream plans must call all three audit primitives inside one `connection.transaction()` and Plan 4 validates rollback behavior. |
| T-02-01-05 | Tampering | Concurrent per-feed ordering | mitigate | Counter-table sequence allocation and unique `(feed_id, feed_sequence)` constraint are the only planned ordering path; Plan 4 adds concurrent integration coverage. |
| T-02-01-06 | Repudiation | Delete snapshot timing | mitigate | `GET_AUDIT_FEED_SNAPSHOT_SQL` locks and projects `feed_properties` before delete; Plan 3 must insert `feed.deleted` before `DELETE_FEED_SQL` removes current state. |
| T-02-01-07 | Spoofing | Already-applied actor constraint | mitigate | Add `030_feed_audit_events_actor_constraint.sql` to precheck legacy `system:%` rows, drop any stale `feed_audit_events_actor_id_check`, and recreate it without the rejected prefix. |
</threat_model>
