- D-21: Unit tests prove create/update action, actor, sequence, and full snapshots.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request -> FeedService | Request bodies are untrusted and must not contain accepted actor IDs in Phase 2. |
| FeedService -> FeedStore | Service passes the fixed causal actor `service:feeds-service`; storage requires it explicitly. |
| FeedStore -> AlloyDB transaction | Current-state mutation, sequence allocation, and audit insert cross into the database together. |
| Feed row -> snapshot JSON | Storage serializes only allowlisted feed values into audit JSON. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | `FeedStore.create_feed` / `update_feed` | mitigate | Use one acquired connection and one `connection.transaction()` for mutation, sequence allocation, and insert per D-04 and CON-01. |
| T-02-02-02 | Spoofing | `FeedService.create_feed` / `update_feed` | mitigate | Pass fixed `service:feeds-service` per D-14 and keep actor fields out of request models; Phase 3 handles trusted human forwarding. |
| T-02-02-03 | Spoofing | `FeedStore` method contracts | mitigate | Require keyword-only `actor_id: str` with no default per D-01 so missing actor is a programming error. |
| T-02-02-04 | Information Disclosure | `_audit_snapshot` | mitigate | Serialize only the D-12 allowlist and explicitly omit worker, heartbeat, fencing, and filename fields; tests inspect before/after JSON. |
| T-02-02-05 | Tampering | Sequence allocation under concurrent create/update | mitigate | Allocate through `ALLOCATE_FEED_AUDIT_SEQUENCE_SQL` inside the transaction; unit tests assert the sequence call and Plan 4 validates concurrent ordering. |
| T-02-02-06 | Repudiation | No-op update suppression | mitigate | Compare normalized stored name/tags before mutation and return current feed without audit when unchanged, preserving no false history per D-05 through D-07. |
| T-02-02-07 | Repudiation | Delete snapshot timing | mitigate | This plan does not implement delete, but it uses the same snapshot helper that Plan 3 must call before hard delete; tests must not weaken the helper allowlist. |
| T-02-02-08 | Tampering | Rollback drift | mitigate | Keep audit insert inside the same transaction; Plan 4 adds a database-backed failing-audit rollback test. |
</threat_model>
