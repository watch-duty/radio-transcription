<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unit mocks -> database reality | Mock tests do not prove rollback, row locks, or concurrent sequence behavior; integration tests cross this boundary. |
| Concurrent storage calls -> AlloyDB | Multiple writers can attempt same-feed mutations concurrently and must serialize safely. |
| Current-state delete -> durable audit history | Integration tests must prove audit rows survive feed deletion with full before snapshot. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Tampering | Transaction rollback path | mitigate | Force database-level audit insert failure and assert feed state plus audit rows roll back together. |
| T-02-04-02 | Tampering | Concurrent same-feed writes | mitigate | Use integration concurrency test to assert unique contiguous `feed_sequence` values and rely on the database unique constraint. |
| T-02-04-03 | Spoofing | Actor validation | mitigate | Invalid/removed actor prefixes such as `system:` must fail at the database constraint and must not be silently rewritten by storage. |
| T-02-04-04 | Information Disclosure | Persisted snapshots | mitigate | Final tests inspect persisted `before_values` and `after_values` for allowlisted fields only and reject worker/heartbeat/fencing/noisy fields. |
| T-02-04-05 | Repudiation | Delete snapshot timing | mitigate | Integration delete assertions must confirm `feed.deleted` remains after `feeds` and `feed_properties` are gone, with full before snapshot and `{}` after snapshot. |
| T-02-04-06 | Tampering | Audit integrity after service/API calls | mitigate | Final targeted tests include service actor propagation and route compatibility so callers cannot build or spoof audit rows. |
| T-02-04-07 | Denial of Service | Local integration validation | mitigate | Integration command is `safe-run -- ... -n 0` and local Docker/Testcontainers execution is approval-gated or left to CI. |
| T-02-04-08 | Repudiation | Missing actor programming errors | mitigate | Final invariant checks reject optional/default storage actor parameters and require explicit actor arguments in tests. |
</threat_model>
